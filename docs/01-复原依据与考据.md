# 复原依据与考据

本文件回答一个问题:**这件作品里,哪些是查来的,哪些是我们自己定的。**

与 `docs/08-已知局限与未做还原.md` 的分工:那边是**边界台账**,逐条写"我们做不到什么、
哪里是推断的";这边是**依据台账**,写"我们凭什么这么做、以及这个'凭什么'有多硬、
能被机器验到什么程度"。两份互为表里,谁也代替不了谁。

要求里写着不许宣称"完美还原""考古级复原"。这句话在**文档层**的落点,就是这份文件:
把每一处的证据等级摊开,让读者能逐条核对,而不是只能选择"全信"或"全不信"。

## 怎么读这份文件

- 每一条事实后面跟 `文件:行`。**没有出处的句子不许写进来。**
- 行号是 2026-09-18 这次工作区状态的读数。文件一改,行号会漂 —— 引用的是**当时的文本**,
  版本对了行号才作数。
- 读不到、量不到的,写成「未验证」,不写成结论。本文件末尾专门列了这类条目。

其中**「无桥墩」是几何断言**,不靠文献:跨内水下无任何实体,这一条是直接可验的
(`blender/tasks/validate_scale.py:2448`,实测 0 个桥墩,`blender/out/validate.json:149`)。

### 1.3 原画不能确定的:尺寸、平面关系、人数、原貌色彩

这一节的每一句都是**原画这个媒介本身的限制**,不是我们偷懒:

- **没有比例尺。** 张择端没有画过带刻度的参照物,原画给不出任何可换算的长度
  (`blender/config.py:8-13`、`blender/config.py:647-648`)。
- **散点透视,给不出可靠的平面关系。** 两岸街道多宽、各家铺面摆在哪个平面坐标上、
  城门与虹桥的相对方位 —— 一律量不出来(`blender/build/00_layout.py:21`、
  `blender/config.py:340-343`、`blender/tasks/validate_scale.py:2481`)。
- **人数与配比数不出来。** 原画卷面上有多少人、各在做什么,散点透视 + 尺幅所限,
  得不出可靠的比例(`blender/config.py:1091-1093`、`blender/build/07_characters.py:47-49`)。
- **摊贩卖什么、各家门口摆什么,无法逐户辨识。**
  (`blender/build/06_props.py:33-34`)
- **色彩原貌没有定论。** 绢本历经近千年,颜料老化、绢质褐变,现状比原貌更暗更黄;
  但"原貌究竟多鲜"本身没有定论(`src/data/basis.json:145-147`)。

### 1.4 尺寸链的根节点是一个**估读值**

整套尺寸的根是"虹桥栏柱间距约 1m"这一处单点假定,由后世研究者(主要是唐寰澄)
据此链式推算全桥尺寸(`blender/config.py:9-13`)。这意味着:

> **1m 若错了,下游所有尺寸等比地错。**

这条边界在三处写着,口径一致:`blender/config.py:13`、`blender/tasks/validate_scale.py:2444-2445`、
`src/data/basis.json:41`。

### 1.5 一条已被证伪、禁止使用的数据

百度百科称虹桥"跨度约 5.28 米"。**528.7 cm 是全卷长度,不是桥跨。**
该说法记在 `blender/config.py:24-27`,并明令"任何脚本都不得引用该值"。
记在这里的理由同 `docs/08`:防止将来有人"查证"时把它当依据捡回来。

## 二、三个等级:有据 / 择一 / 推断

### 2.1 数据结构

`src/data/basis.json` 是依据条目的唯一数据源。顶层四个键
(`src/data/basis.json:2-17`):`schema`、`grades`(等级定义)、`caveat`(整表的总声明)、
`entries`(条目数组)。每个条目的字段:

| 字段 | 含义 | 出处 |
|---|---|---|
| `id` | 稳定标识 | `src/data/content.ts:80` |
| `topic` | 一句话主题(面板上的标题) | `src/data/content.ts:81` |
| `claim` | 本作主张了什么 | `src/data/content.ts:82` |
| `basis` | **凭什么** —— 文献原文或"无" | `src/data/content.ts:83` |
| `grade` | A / B / C | `src/data/content.ts:84` |
| `assert` | 对应的机器断言原文(**可选**) | `src/data/content.ts:86` |
| `caveat` | 这一条的边界(**可选,但大多有**) | `src/data/content.ts:87` |

三个等级的定义照抄在 `src/data/basis.json:3-16`:

- **A 有据** —— "有明确文献记载或考古材料支持,且属学界基本共识。改动它等于改错。"
- **B 择一** —— "有依据,但存在多种解释或多种做法,本作择其一。换一种做法未必是错的。"
- **C 推断** —— "原画与文献都给不出答案,是本作为了把作品做完而作的推断或取舍。**不是复原成果**。"

整表的总声明(`src/data/basis.json:17`,面板顶部会原样渲染):

> 本表的作用不是证明「做得对」,而是把**哪些是查来的、哪些是我们自己定的**分开。
> 凡是标 C 的,请当作本作的设定,不要当作宋代的事实引用。

### 2.3 面板怎么把等级呈现出来

`src/ui/panels/BasisPanel.ts`。三条设计决定值得写下来,因为它们都是为了**不误导**:

1. **默认全部显示,不是默认只看 A。** 文件头注释原话:默认只看 A 会让读者以为
   "这个作品几乎全有依据",而实际上相当一部分内容是 C 级推断 ——
   "把 C 藏起来是最容易发生、也最不该发生的一种误导 —— 它不需要说谎,
   只需要把不利的那部分折叠起来"(`src/ui/panels/BasisPanel.ts:7-11`,
   初始集合见 `:24`)。
2. **筛选按钮上直接标出各等级有几条**(`src/ui/panels/BasisPanel.ts:39-57`,
   条数由 `basisCounts()` 现算,`src/data/content.ts:135-139`)。
3. **机器断言单列一行,与正文分开**(`src/ui/panels/BasisPanel.ts:70-75`)。
   它用的是 `<code>` 而不是普通段落 —— 读的人一眼能看出"这一条有机器在盯着",
   而没写断言的条目**不会**显示任何暗示已验过的标记。

等级徽标是同一套定义,景点简介面板复用同一份 `GRADES`
(`src/ui/panels/SpotPanel.ts:49-53`),不各写一份。景点面板的"边界"块
在样式上**与正文同权重,不弱化**(`src/ui/panels/SpotPanel.ts:69-74`)。

### 2.4 读取层拦住了三类错

`src/data/content.ts` 不是简单的类型转换,它在启动时**主动抛错**:

| 拦住的错 | 出处 |
|---|---|
| 条目少于 12 条(验收线) | `src/data/content.ts:105-111` |
| 某条的 `grade` 在 `grades` 里没有定义(拼成 `b` 或 `A+`) | `src/data/content.ts:121-128` |
| 景点简介少于 3 条 | `src/data/content.ts:42-48` |
| 某条景点简介 `intro` 为空 | `src/data/content.ts:56-57` |
| **某条景点简介没写 `caveat`** | `src/data/content.ts:58-63` |

最后一条的报错文案就是这份文件的立论,原文:

> 每条简介都必须写明它**不可知**的部分 —— 只写"复原了什么"而不写"哪里是推断的",
> 就是在暗示复原程度比实际更高。

**结论:在景点简介这一层,"不写边界"不是一种风格选择,而是启动就会失败的硬错误。**
`src/data/hotspots.json` 的 5 条全部带 `caveat`(行 16、29、42、55、68),
等级分布为 **B 3 / C 2**,没有一条 A。

## 三、同一批字母,三套口径 ⚠️

**这是本文件最该被认真读的一节。**

A / B / C 这三个字母在本项目里被用了三次,而**三处的解释不是同一件事**:

| 出处 | A | B | C |
|---|---|---|---|
| `src/data/basis.json:3-16` | 有据:文献/考古材料 + 学界共识 | **择一**:有依据但多种做法,本作择其一 | 推断:原画与文献都给不出答案 |
| `blender/config.py:15-19`、`:45-50` | 有文献或实物旁证 | **由 A 级推算**,误差随层数放大 | 为观感或工程可行性选定,无考据支撑 |
| `docs/08-已知局限与未做还原.md:14-17` | **原画里可直接量出的比例关系** | **有文献或形制依据,数值经本项目换算** | 本项目为可读性所做的编排 |

三处对 **B** 的说法分别是"择一""推算""换算",对 **A** 的说法分别是
"文献支持""文献旁证""原画可直接量出"。它们彼此不冲突,但**也不相等** ——
一个标着 B 的条目,读者无法确定它到底是三者中的哪一种。

⚠️ 更要紧的是:`docs/08:14` 那句写的是"口径与 `blender/` 各脚本里的 `Reliability X`
标注**一致**"。以代码为准,这句话**不成立**:三处是三套定义。

### 3.1 而且这个等级不是一个字段,机器筛不出来

这一条 `docs/08:20-25` 已经说过一遍。本文件再写一次,是因为它同时是**这份依据台账
的能力边界**:

- `class Reliability(str, Enum)` 声明在 `blender/config.py:45-50`,
  **全仓库没有任何一处引用它**。它唯一被提到的地方是 `blender/config.py:15` 的文件头注释。
- `blender/config.py` 里共 **39 处**写着 `Reliability A/B/C`(A 2 / B 14 / C 23),
  其中一部分是行内常量注释(如 `SPAN` 的 `:80`),一部分是段落说明(如 `:300`)。
- 四块 GLB 合计 **379 个节点**,**没有一个**带 `reliability` 或 `qm_reliability` 属性。
- 物体上的 `qm_note` 是"复原依据备注(边界声明)"(`blender/lib/tag_utils.py:51`)。
  379 个节点里 **225 个**带 `qm_note`,而其中**文字里出现 `Reliability` 三个字的只有 3 个,
  且三个都是 C**:
  - `岸线_地坪` —— "郊野起伏 ±1.2m 为观感推定(Reliability C);正弦叠加生成以保证跨版本可复现"
  - `岸线_路` —— "街道宽 9m、纤道宽 2.2m,均为功能推定(Reliability C),非原画实测"
  - `河道_驳岸` —— "木桩护岸 + 压顶石;侧脚 0.10m 为观感推定(Reliability C)"

**所以:没有任何脚本能按可靠度筛选物体。** 想看某件东西是几级,只能读它的注释或
`qm_note` 文字,不能查。

### 3.2 一处与代码不符的表述

`src/data/basis.json:41` 的 caveat 里写着:

> 在 blender/config.py 中保留为可调参数并带 reliability 字段。

**这句话的后半截与代码不符。** `blender/config.py` 里**没有** `reliability` 字段;
可调参数(`SPAN`、`RISE` 等常量)确实在那里,但"带 `reliability` 字段"没有实现 ——
只有注释里的文字标注。

## 四、为了让画面成立而补的部分

### 4.1 一处与面板文字不符的:建筑"内部"

`src/data/basis.json:152`(面板上会显示)写的是:

如实转述:**不做榫卯不是为了省事,是因为做上去就错了。** 这是本文件被引用的第一处

## 五、机器断言能证明什么、不能证明什么

`blender/tasks/validate_scale.py` 跑完会写 `blender/out/validate.json`。当前实测:

| 项 | 值 | 出处 |
|---|---|---|
| 断言总数 | **59** | `blender/out/validate.json` 的 `checks` |
| 通过 / 失败 / 跳过 | **59 / 0 / 0** | 同上,`pass`/`fail`/`skip` |
| 阶段 / 逾期未做 | stage **2** / overdue **0** | 同上 |
| 边界声明条数 | **24** | 同上,`boundaries` |

⚠️ **"59 条全绿"这句话本身很容易被读过头。** 脚本自己把能力边界写在了
`BOUNDARIES` 里(`blender/tasks/validate_scale.py:2441-2516`),逐条转述其中与本文件
直接相关的几条:

| 断言 | **不能**证明的事 | 出处 |
|---|---|---|
| 全部形制断言 | 只证明"几何与 config 声明的尺寸一致",**不证明"声明符合北宋原物"** | `:2442-2443` |
| 无榫卯 | 由"无榫卯命名对象 + 索绑在每个节点上存在"间接支撑,**无法从三角形网格反推木构件的连接工艺** | `:2446-2447` |
| 无桥墩 | 这一条是**直接可验**的(跨内水下无实体) | `:2448` |
| 屋面形制白名单 | 证明的是**声明(`qm_roof`)里**没有硬山,**不证明几何里真的没有** —— 悬山与硬山只差"山面有没有把檩头挑出去",没有任何三角形可以反推 | `:2462-2465` |
| 城墙无包砖 | 只能证明**没有独立的砖层对象/材质**;单一材质的墙体在渲染上仍可能被贴上砖纹 | `:2475-2477` |
| 彩楼欢门 7 座 | 只证明**本场景按 7 座布置**,不证明还原了原画中可辨的那 7 家;本场景只有 8 栋铺面,**密度是被放大的** | `:2484-2487` |
| 绑扎、无斗拱 | 索环数是真从顶点数反算的(这一条是硬的),但"杆件之间没有榫卯"**无法从三角形网格反推** | `:2488-2492` |
| 贴图 | 全是**程序化生成**的,没有任何一张来自实物照片或扫描件;法线与粗糙度由同一高度场派生,物理自洽**不因此就更接近真实瓦片** | `:2498-2501` |

这与 `docs/08` 第 4.2 节说的是同一条边界的两面:那边写"断言量不到什么",
这边说"断言只能量到声明与几何的一致性"。

**凡是机器判不了的事,就明说判不了** —— 不要用一条绿色的断言去暗示已经验过了。

### 6.2 素材是怎么到手的(以及它**不是**什么)

1. **网页的"原卷"面板** —— 四段拼成一条可横向滚动的长条,惰性加载,失败逐张报

### 6.3 五个景点与原画的对应关系

**这是一件交互作品,不是考古复原。不得据此宣称形制准确。**

## 附录:本文件里的数字是怎么数出来的

#   (需解 GLB 的 JSON chunk,见本次的分析方式;核心是遍历 nodes[].extras)
# → 379 节点 / 225 带 qm_note / 3 条 qm_note 写了 Reliability
